# Что дальше

Задел на следующие версии. Сначала тестовый прогон, потом доработки по его итогам: многое из списка ниже стоит менять только после того, как станет видно, что мешает на практике.

## Тестовый прогон

Один настоящий спринт: одна тема, две-три книги, все этапы и первые три дня курса. Что проверить:

- [ ] Видит ли система книги целиком, или Claude Projects переходит на поиск по фрагментам. Сколько книг помещается без него.
- [ ] Собирает ли «утверждаю» все правки в итоговую версию без потерь.
- [ ] Ставит ли модель метки источников и честно ли отделяет книги от общих знаний.
- [ ] Не приписывает ли голос автора себе выдуманные случаи.
- [ ] Правильно ли модель сама заполняет входные данные урока из плана и насколько утомительно заполнять их вручную.
- [ ] Укладываются ли задания во «Время в день».

## Доработки по итогам прогона

- [ ] **Промт куратора.** Принимает результат дня, сверяет его с форматом задания, начисляет баллы, ведёт чекпоинты, выдаёт следующий день и при необходимости подстраивает его.
- [ ] **День 0.** Памятка участника: правила, дневник, таблица баллов, списки наград и наказаний, ритуал входа. Замер цели в первый день и повторный замер в последний.
- [ ] **Эталон голоса.** По 300–500 слов образцового текста на каждый из трёх голосов. Брать из лучшего дня прогона после авторской правки.
- [ ] **Пример прогона** в папке `examples/`: параметры, итоги этапов, пара готовых дней.
- [ ] **Проверка готового дня.** Короткий чек-лист в конце этапа урока: объём, возражение, доля задания, запретные слова.

## Идеи без срока

- [ ] Интрига для автора, который сам же проходит курс: он видит весь план заранее, и механика «есть схема» на нём почти не работает. Один из вариантов: план без формулировок заданий.
- [ ] Упаковать репозиторий как плагин Claude Code, чтобы ставить навык одной командой.
